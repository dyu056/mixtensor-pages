协议与成本
  • train / validation / test：1024 / 256 / 256；目标按训练标签统计量归一化。
  • 128 个随机架构；body family 分隔元模型训练、验证与候选集合；相同 body 的循环变体不跨集合。
  • 任务模型：width 64，400 epochs，batch 256，AdamW lr 0.001，clip 1，FP32；参数量与计算量仍有差异。
  • 元模型：祖先依赖 mask 的图 attention，2 layers × 4 heads，width 32；3 个拟合种子 ensemble；另有图统计 ridge 对照。
  • 所有候选预测先冻结，再查询候选 loss；最终架构名单先冻结，再评估 test。
  • 每 epoch 保存模型、优化器与完整随机数状态，可按原协议续训。

如何解读这次结果

  • 只覆盖一个固定 Adding 实例；不能由此证明跨任务泛化。
  • 候选池与入选架构在 trial 间重用，不能将 10 个 trial 当作独立样本宣称统计显著性。
  • 元模型预热数据有额外成本；本轮不声称总计算预算优于从零随机搜索。
  • 模型 attention 权重不是节点的因果贡献；当前阶段先检验搜索效用。
